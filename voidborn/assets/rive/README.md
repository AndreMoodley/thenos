# assets/rive — the living entity (authored art)

These `.riv` binaries are authored in the **Rive editor** and are not generated by code, so they are
not in the repo yet. Until they ship, `src/entity/RiveEntity.tsx` renders the metric-reactive
`FallbackEntity` (a real, live-reacting orb). Drop the files here and wire them in
`src/entity/riveSources.ts` (uncomment the `require`s) — Rive then takes over with zero other changes.

## Required files (one per form line)

| File | Form |
|---|---|
| `void.riv` | Void (free origin) |
| `beast.riv` | Beast (premium) |
| `humanoid.riv` | Humanoid (premium) |
| `transcendent.riv` | Transcendent (earned via Heavenly Restriction) |

## Each file must contain

- **Seven stage artboards** named `<Form>_<Stage>`: `Void_Embryo`, `Void_Awakening`, `Void_Forming`,
  `Void_Tempered`, `Void_Ascendant`, `Void_Sovereign`, `Void_Divine`. The screen selects the artboard
  for the **computed** stage (never stored). (Bloodlines ship an alternate stage-artboard set inside
  the same file.)
- **One state machine** named **`EntityState`** (see `riveSources.STATE_MACHINE`) with number inputs:
  - `ki` (0–100) → eye brightness / aura integrity
  - `shadowLevel` (1–5) → appendage spread / pulse rate
  - `streak` (≥7 → bonus orbit) and `realm` (1–7 → silhouette)
  - `mastery` (originArtMastery) → glow
  - `corruption` (0/1) → corrupted overlay
- A **`rebirth`** one-shot trigger for the birth set-piece.

Keep files small (Rive's strength). Logic lives **inside** the state machine; the app only pushes
inputs (`src/hooks/useEntityInputs.ts` → `RiveEntity`).
